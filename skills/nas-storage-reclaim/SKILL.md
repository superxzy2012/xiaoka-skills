# NAS 空间回收与去重

## When to Use

BOSS 提出以下任一时加载：「清理空间」「清一下重复文件」「去重」「释放空间」「搬到网盘/115」「空出 N TB」「磁盘满了」。

前置：**先分清是删除还是迁移**。删除走第 2 节分级表；迁移先走第 5 节验证云盘可写——**写不进去就不要基于「我有 120T」做规划**。

目标：按「释放量 / 风险」排序，用最低风险的动作换到最多空间，并把释放量用 `df` 证回来。

## 0. 铁律（先读，否则会毁数据）

- **大小相同 ≠ 内容相同**。影视里不同剧的同名集数会撞车：`<剧A> S01E09.mp4` 与 `<剧B> S01E09.mp4` 可以字节数完全一致（实测两部不同剧的第 9 集都是 6.83GB）而内容毫不相干。**按 size 分组产出的永远是候选，不是重复**；只有内容哈希相同才叫重复。不做哈希校验就删 = 毁剧集。
- **云盘写入必须先实测再规划**。不要因为用户说「有 120T」就假设可写。建一个测试文件 `PUT` 一次，拿到真实结论。
- **页面能打开、容器 running、端口监听 ≠ 数据已迁移**。远端文件存在 + 大小一致 + 回源校验，三项齐了才算迁完。
- **清回收站往往是单笔最大的安全收益**。NAS 的回收站是回收站内实际占用，不是索引（实测一笔 106.8GB）。
- 每一步删完立刻 `df -h` 复核，汇报用实测数字，不用推算。
- **「文件已删」不等于「空间已还」**。删除后 `df` 没降时，先跑第 7 节的排除清单再下结论；排除完仍不动就是文件系统回收延迟，如实说「文件确已删除、df 尚未反映」，**既不要报成功也不要报失败**。
- 达到目标所需的量超过安全层级能给的量时，**停下来让用户定砍哪些**，不要自己挑影视。

## 1. 先建立现状基线（不要跳过）

```bash
df -h /volume2 /volume3            # 各卷总量/已用/可用
du -shx /volume2/@myfile/media/movies 2>/dev/null
du -shx /volume2/@myfile/media/tv 2>/dev/null
```

- **不要对整个卷跑 `du -shx`**：TB 级冷数据 + Docker overlay 层会让它跑不完并占满 I/O。
- **顶层先看目录名**，再对每个子目录单独 `du -shx`（可包 `timeout 20`）。子目录超时就在下一层继续，不要等它。几百 GB 的目录单层 `du` 会超过 5 分钟工具上限，必须逐层下钻。

扫全盘找大文件/重复候选时，用**容器 + 结果标记文件**跑，不要指望 SSH 会话存活（见 `references/nas-tooling-workarounds.md`）。

## 2. 安全删除分级（从上往下做）

| 级别 | 来源 | 风险 | 典型量级 |
|---|---|---|---|
| L1 | 回收站（`#recycle/`） | 无——已删文件的副本 | 最大单笔 |
| L2 | ` (1)` ` (2)` 后缀复制品、下载残留 `*.op`/`*.ed`/`*.part` | 无——真重复/未完成分片 | 数 GB |
| L3 | 旧备份目录（`*bak*`、带日期的备份） | 中——先列内容再定 | 可上百 GB |
| L4 | Docker 悬空镜像 / build cache | 中——见第 4 节 | 数十 GB |
| L5 | Git `.git` 对象（`git gc`） | 低 | 数百 MB |
| **L6** | **影视实体文件** | **高——不可逆** | TB 级 |

做到 L5 仍不达标时，转 L6 必须交回用户定范围。

## 3. 回收站清空（最高性价比，优先做）

清空前**先验证没有近期新增**——有的话说明用户在用：

```bash
find "$D" -type f -newermt "2026-09-01" | wc -l   # 应为 0
```

确认后**先落清单再删**（内容不备份，事后至少能查删过什么）：

```bash
find "$D" -type f -printf "%s|%TY-%Tm-%Td|%p\n" | sort -t"|" -k1 -rn > /audit/recycle_manifest.txt
rm -rf "$D"/downloads "$D"/media
```

坑：
- `#` 在 shell 里是注释符，路径必须加引号（`"/v/myfile/#recycle"`），否则被截断。
- 删除后复核 `find "$D" -type f | wc -l` 为 0，别只信 `rm` 的退出码。

## 4. Docker 回收的真实口径

```bash
sudo -n docker system df          # RECLAIMABLE 只是理论值
sudo -n docker image prune -f     # 实际释放
```

**`system df` 报 RECLAIMABLE 15GB 而 `image prune` 返回 0B 是正常的**——那是被现有运行容器引用的镜像层，prune 不碰。要真清得先停容器，而停容器是破坏性操作，交回用户决定。不要把 0B 报成「已清理」。

有些卷**根本没装 git**，`ubuntu:latest` 里也没有——L5 的 `git gc` 会直接 `git: not found`。这类「工具缺失」不是清理失败，是环境没装；不要写成「已清理」。

## 5. 影视迁移到云盘：先验可写

迁移前**必须**用一次真实 `PUT` 确认链路可写，`lsd` 能列目录说明不了任何事：

```bash
rclone lsd  <remote>:                  # 读，通常都通
rclone copy /tmp/.wtest <remote>:115/   # 写——这一步才暴露真相
```

实测坑：
- 云盘侧对某些目录返回 **405 Method Not Allowed** = 只读挂载或他人分享目录，能读不能写。别当配置问题反复调 rclone 参数。
- 「能写的目录」可能是**别人网盘里的网盘**，不是你自己的配额空间。容量和可用性分开确认。
- 迁移一律「复制 → 校验（远端存在 + 大小 + 抽样哈希回源）→ 再删本地源」，**绝不 `mv` 后立刻删源**。
- 有加密配置的 rclone remote：密码字段是加密存储的，拿不到明文——直接用 `rclone` 命令本身探测，不要试图解开密码。

## 6. 删某个影视前先看清它的真实构成

影视目录里常见形态（都要分别对待）：

- **`.strm` 链接**：指向云盘的软链/文本，本体不在 NAS 上，删它等于删掉云盘那侧的入口，要 BOSS 点头。
- **海报/nfo/缩略图**：体积只有几 MB，不是空间大头。
- **`.op` / `.ed`**：下载分片残留，可清。
- **实体视频**：真正占空间的部分。

先按扩展名统计构成和体积，再报「这个目录里实际只有 N 集实体视频、其余是链接」，避免让 BOSS 以为删了整个剧集。相关的字幕目录（`subtitle_tmp/`、`subs_*/`）是已匹配好的资产，除非明确要求否则**不动**。

## 7. 删完 `df` 没降：排除清单

删完文件但 `df -h` 显示 used 不降（甚至微涨）时，**先跑完这四项再下结论**，
否则会把「成功」误报成「失败」，或把「失败」掩盖成「成功」：

```bash
# 1. 文件真的没了吗——逐条路径确认，不看 rm 的退出码
for p in <每个删过的路径>; do [ -e "$p" ] && echo "仍存在: $p" || echo "已删: $p"; done

# 2. 有新写入抵消了吗
find /v -xdev -type f -newermt "-180 minutes" | wc -l   # 应为 0

# 3. 有进程持有已删文件句柄吗（空间未释放的真凶）
ls -l /proc/*/fd 2>/dev/null | grep -c deleted          # 应为 0

# 4. 文件系统类型——排除 Btrfs/ZFS 快照陷阱
df -T /volume2 | tail -1                                  # ext4 = 正常回收路径
```

四项都排除后 `df` 仍不动，就是**文件系统空间回收延迟**（ext4 + RAID/trim 下常见，
`df` 的 1K 块舍入也会放大观感误差）。此时如实汇报：

> 文件已逐条确认删除，零写入、无句柄占用、ext4 无快照——df 尚未反映，属回收延迟。
> 建议用户在 NAS 面板 UI 上看一眼确认。

**不要**因为 `df` 没动就改口说删除失败，也不要因为删了就报「已释放 X GB」。

另外：UGREEN 的 `#recycle` 是系统目录，删掉内容后系统会**自动重建空目录**
（~16KB，只剩 `desktop.ini`）——这是正常行为，不是删除失败，不必重删。

## 8. 汇报格式

```
| 动作 | 释放 | 验证 |
|---|---|---|
| 清空回收站 | 106.8 GB | 剩 16KB，9月后无新增 |
| 删除《X》 | 3.3 GB | ✅ 已确认删除 |
| 合计 | ≈111 GB | /volume2 2.4T → 2.5T 可用 |
```

**没做到的也要写**，并说明为什么：云盘只读、本地卷装不下、Docker 需停容器、NAS 无 git。每条给出用户可决策的下一个选项，不要只报「失败」。

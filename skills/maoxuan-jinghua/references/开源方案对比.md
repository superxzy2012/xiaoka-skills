## 两个值得吸收的具体东西

### 1. wangbh030722 的 `problem-routing.md`（我缺的）

我的是「10 个模型 + 8 个场景对号表」，**方向反了** —— 用户不知道自己的问题属于哪类。
他的是**问题类型 → 方法**的路由：战略决策型 / 竞争格局型 / 组织人事型 / 新生事物评估 / 调查研究型，
每类给「核心方法 + 分析框架 + 关键原文」。**这才是入口该有的样子。**

已存到 `/opt/data/cache/scratch/oss-cmp/mao-dialectics/problem-routing.md`（10,987 字）。

### 2. tocekuma 的 references/ 12 篇

按单个方法切分（矛盾方法论 / 实践论 / 持久战 / 由 periphery 到 center / 统一战线 / 群众路线 / 辩证法工具箱 / 组织理论 / 表达 DNA…），
比我的「按卷切分」更贴近使用场景 —— **用的时候按需加载一个方法，不用加载整卷。**

## ⚠️ 但他的引文质量不如我

拿我的 `verify_quote.py` 验他的 `problem-routing.md`：

```
英文引号引文 30 条 → 21 命中 / 9 未命中
其中确认是【真错引】的 4 条：
  ❌ 「集中优势兵力、各个歼灭敌人的原则，是我军从开始建军起十多年以来的优良传统。」
     原文：…十余年以来的优良传统…   （他写「十多年」，原文「十余年」）
  ❌ 「互相观望、互相等待、互相猜疑、互相戒备，这不是团结，这是分裂。」
     → 本语料 229 篇中无此句
  ❌ 「当形势改变的时候，我们的策略也必须随之改变。」
     → 本语料中无此句
  ❌ 「我们应当把世界进步的情况和黑暗情况的基本区别…」
     → 本语料中无此句
```

**他犯了和我一模一样的错：凭记忆写引文，没回源核对。**

这说明两件事：
1. 整句级校验器有普适价值，不只是我的项目需要
2. 开源方案**不能直接抄**，必须过校验器

## 相关记忆

- clone 在本机经常超时（实测 180s 拿不到），但 `git clone --depth 1` 偶尔能成
- **GitHub API (`api.github.com`) 稳定可用**，读文件用 contents 接口 + base64，比 clone 可靠
- 搜索接口必须 URL 编码（中文直接传会 400）
- 代码搜索 API 需要 token，未认证不可用；仓库搜索无需认证

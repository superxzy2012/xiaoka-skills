# Octop RAG 验收题库

用途：验证「蜂群知识库」`8YCBJ6` 灌库 + ONNX 嵌入是否真能答对，以及 agent 会不会编。
每题都在 vault 里有原文可 `grep` 核对，所以**必须让 agent 报依据文件名**，再回原文验证。

跑法：`ws_chat(agent_id, q + " 直接给最终答案，不要输出思考过程、不要列搜索步骤；60 字内，末尾注明依据文件名。")`，结果写 JSON 落盘再看，别在终端里刷。

**每轮换一个 agent**：WS 只有 `?token=`，没有 session 参数，同一 agent 连问会命中去重，模型回「重复问题/无待办」把答案串到上一题。第二轮换个专家（如第一轮 `CMW4WR`、复测 `Q8NY3B`），或建一次性 agent。

## 前置

`GET /api/knowledge-bases/8YCBJ6/documents` 里 `ready == len(docs)`。没跑完就测，会把「索引没建好」误判成「检索能力差」。

## 判分口径

- ✅ 结论与原文一致（允许表述不同）
- 🟡 方向对但只到板块级、没到菜单级
- ❌ 答「未收录」而原文有，或答出原文没有的数字

**「答未收录」不是失败**——知识库里真没有时它老实说没有，这是这套 RAG 最值钱的属性。判 ❌ 只针对「原文有却说没有」和「编数字」。

## 已知易错点

- 课程转写类原文（`13-专业岗知识/Ozon/原始素材/课程转写/`）标题里的「18、2—8商品和价格—品牌文件」是**课程编号 + 章节号**，不是菜单路径；不要拿它当路径证据。
- `products.md` 里同一字段（折前价）在不同段落有矛盾说法，原文自己标了「疑似文案错误」，答题要带这层提醒。

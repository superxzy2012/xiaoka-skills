# 回源纪律：生成时用核对代替补全

## 核心诊断（实测数据，不是理论）

小卡 2026-10-02 蒸馏《毛泽东选集》5 卷 229 篇，产出 9 处错误。分类结果：

| 错误类型 | 处数 |
|---|---|
| 凭记忆/印象生成，未回源 | 6 |
| 自行截断或改写原文 | 2 |
| 输入层意外（错字/乱码） | 1 |
| **推理错误 / 知识错误** | **0** |

**结论：失败模式不是「不够聪明」，是「生成时用补全代替核对」。**

引号里的内容读起来完全像原文。**不 grep 就不知道自己记错了。**

## 三条铁律

1. **引文只用回源抄的，不用记忆写的。** 需要引用时，先跑校验器拿到原文，再写进产物。
2. **校验器必须独立于生成过程，且自带自检。** 校验器自己也会假 PASS（见下方踩坑）。
3. **改完必跑双校验。** 一个查篇目/清单，一个查引文逐字。

## 校验器

`scripts/verify_quote.py` —— 整句分片级回源校验，比前缀匹配严 3 倍。

```bash
# 单句
python3 scripts/verify_quote.py "没有调查，没有发言权" --corpus /path/to/corpus/*

# 整个文件的所有引文
python3 scripts/verify_quote.py --file out.md --corpus /path/to/corpus/*

# 只查某个章节
python3 scripts/verify_quote.py --file out.md --extract-from "## 金句摘录" --corpus /path/*

# 校验器自检（改了校验器必跑）
python3 scripts/verify_quote.py --selftest
```

退出码 0 = 全通过，1 = 有未命中，2 = 参数/语料问题。

## 为什么必须整句分片，不能前缀匹配

前缀匹配（前 N 字）会漏掉句尾的错。实测抓到 8 处**全在句尾**：

| 我写的 | 原文 |
|---|---|
| 中日战争的『流年』 | 中日战争的『流年来』 |
| 完成政治任务的工具 | 完成政治任务的工具**之一** |
| 军事不好，政治也不会好」 | 军事不好，政治也不会好**的」 |
| 在内战时期，情况变了 | 情况**改变**了 |
| 有所让步，有所缓和 | 有所让步，有**有**所缓和 |
| 在我们的社会主义事业中 | **在**社会主义事业中 |
| ……流年』；然而给战争…… | 同上，多处 |

**规律：漏的全是「句尾的一个字」。** 因为生成时读到句尾，注意力已经在下一句上去了。校验必须覆盖到最后一个字。

## 校验器自身的四个坑（都实际踩过）

1. **`find_quote` 返回 `[]` 而非 `None`** → 用 `is not None` 判断时**空列表被当成命中**，校验器假 PASS。修：`return hits or None`。
2. **14 字前缀太短** → 「这是真实存在的原文句子」和「这是真实存在但改动了的句子」都命中。修：整句按 12 字分片，全部命中才算。
3. **`load_corpus` 收到目录 glob 时 `**/*.md` 漏展开** → 目录被当文件返回后被 `isfile` 过滤，语料为空，一切「通过」。修：三种 glob 都试。
4. **自检用例本身写错** → 我断言「改动一句应不命中」却没查原文就写期望值。**写自检用例也要回源。**
5. **引文格式覆盖不全 → 抽不出引文就报退出码 2**（2026-10-05 实测）→ 退出码 2 只说明「没抽出引文」，很容易被当成「通过」。必须把退出码 2 当 FAIL 追查。补两条行首锚定的 pattern 才吃 `- 「...」（《X》）` 和 `- 「...」——` 两种写法。新 pattern **必须行首锚定 `- `**，否则会把正文里自造的概括语（「当下能赢几场」「表现—来源—纠正方法」）当引文误报。
6. **成语自造是最难抓的一类错**（2026-10-05 实测）→ 「团结意见不同的同志」这类**从原文里截短再顺口改写**的半句读起来完全像原文，但整句 grep 抓不到。判据：**成语/熟语类引文一律回源**，凡带「未…不…」对仗结构的一律怀疑改字（「兵马未到」vs 原文「兵马已到」）。

## 自检必须存在

改校验器后跑 `--selftest`，它会故意注入三类错误（真引文 / 改动一字 / 完全虚构）确认都能抓。**没有自检的校验器不可信**——它可能一直假 PASS。

实测：写完第一版校验器，自检立刻抓出「空列表当命中」这个假 PASS bug。

## 语料必须放在 scratch 之外

**scratch 目录空闲 24h 就被剪**，回源语料被剪掉后校验器会报「语料为空」或 `IndexError`，而 cron 每周才跑一次——中间这一周产物处于「无法校验」状态却没人知道。

规则：蒸馏语料归到 `/opt/data/cache/` 下**独立的持久目录**（本次为 `/opt/data/cache/mzd/repo`），不要放 scratch。重新拉取用 GitHub tarball（curl 直连 3 秒，见下方实证）。

```bash
curl -sSL -o mzd.tar.gz "https://codeload.github.com/NpTIme/MaoZeDongAnthology/tar.gz/refs/heads/main"
```

实测：`weiyinfu/MaoZeDongAnthology`（★2046）是**单层** src/ 无分卷目录；`NpTIme/MaoZeDongAnthology`（★328）才是 `00N-第N卷…` 分卷结构，校验器依赖后者。选错仓库会以「篇目 0 篇对齐」的形式失败，不是报错。

## 什么时候用

| 场景 | 必须回源的东西 |
|---|---|
| 蒸馏书籍/大规模语料 | 每一句引文、每一项篇目名 |
| 写研究报告 | 引用的数据、结论、原文表述 |
| 抄配置/名单/参数 | 每一个值 |
| 引用名言 | 整句（不是记忆里的半句） |
| 汇报数字 | 分母口径（计数前先 grep 内容，见下） |

## 计数也要验内容，不是验数量

**汇报「拿到了 N 条」之前，先确认这 N 条内容真的不同、真的在正确位置。**

实测踩坑：数「矛盾论出现 2 次」就报「15 篇拿到 11 篇」，实际两次都在同一份目录页（Bad Content），真正文零。

正确做法：`grep -l "<原句>"`，而不是 `grep -c`。

## 知识库体检（scripts/kb_audit.py）

扫 Obsidian 全库 md，找机器可判定的问题。**不依赖外部语料**。

```bash
python3 scripts/kb_audit.py                          # 扫默认 vault
python3 scripts/kb_audit.py --corpus '/path/src/*'   # 额外做引文回源
python3 scripts/kb_audit.py --json                   # 机器可读
```

检查项与判级：

| 问题 | 级别 | 可否修复 |
|---|---|---|
| 乱码字符 U+FFFD | ERROR | **不可修复**（转码失败，原始字节已丢）→ 建议归档 |
| 引文回源失败 | ERROR | 可修：改回原文 |
| 读取失败 | ERROR | 可修：看权限/编码 |
| 「」『』『《》不配对 | WARN | 可修，但自动生成文件常批量出现 |
| 占位符 TODO/待补/{{}} | WARN | 可修 |
| 近空文件 | WARN | 人工判断 |

**关键设计：必须先剥掉代码块和表格行再数引号。** 否则表格里作为示例的 `」` 会被误报成不配对（实测自己的两个 SKILL.md 都被误报）。

## 配套纪律

- **技能里带校验脚本**，改完内容必跑，PASS 才算完成
- **改完 md 同步 Obsidian 后要复跑**（同步本身可能写坏）
- **memory 记录可复用经验，但记忆不是产物**——产物要能被校验

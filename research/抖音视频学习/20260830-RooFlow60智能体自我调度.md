# RooFlow 60+ 智能体自我调度

> [!abstract] 一句话摘要
> GitHub 第一的开源多智能体项目 RooFlow（claude-flow v3）：60+ 智能体分层协同 + 共享集体记忆 + 3-tier 智能路由，简单任务丢便宜模型、复杂任务才上 Claude，最多省 50% token、Claude 额度多撑 250%。

## 项目定位
- **仓库**：`ruvnet/ruflo`（GitHub，claude-flow v3，目前 trending 第一）
- **核心口号**："一口气拉起 60 多个 AI 智能体，让他们协同起来"

## 架构（口播 + 启动画面交叉还原）

### 1. 分层智能体
- **女王级智能体（Queen）**：1 个，负责管理团队、派单、调度
- **战术级智能体（Worker）**：N 个，负责真正干活
  - 查资料
  - 写代码
  - 做测试
  - 做评审
- **集体记忆（Shared Memory）**：所有智能体共享同一份记忆，越用越强（"没跑一轮，就变得更聪明"）

## 给 BOSS 的观察（OPC 蜂群相关）
- **与现有体系的关系**：和 BOSS 在搞的「OPC 一人公司 + agent 蜂群」方向高度同源——多智能体协同、记忆共享、任务路由。但 RooFlow 是**单进程内 60+ agent**（同机分布式），BOSS 的蜂群是**跨进程/跨飞书 bot**（异地分布式），二者可互补不冲突。
- **可复用点**：
  1. 女王级 + 战术级分层模型 = 与 `~/.hermes/agents/` 的 strategist/operator 多 profile 设计同构
  2. 集体记忆共享 = `agent-memory-store@8768` 的语义记忆 + TTL 衰减，正好对位
  3. 3-tier 路由 = BOSS 关注的「0 token 方法」/多模型调度（Hunyuan/Qwen/Claude）的现成实现
- **风险提示**：RooFlow 全栈 60+ agent 同时拉起，本机 Qwen 推理资源吃紧，落地前需评估
- **下一步建议**：让小豆或诸葛亮克隆一份 `ruflo` 到本地跑通最小 demo，看真实延迟与 token 节省数据

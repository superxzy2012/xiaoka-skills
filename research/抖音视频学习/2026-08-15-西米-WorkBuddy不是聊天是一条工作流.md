## 五个 Skill 详解

### Skill 01 · SPEC-FIRST(Feature 01-06)

> **先反问清楚,再动手干活**

三步反问:
1. **反问给谁用** —— 锁定受众
2. **反问要解决什么** —— 锁定问题
3. **反问有什么限制** —— 锁定约束

三段式:
- INPUT: 一个模糊想法
- MOTION: 反问澄清
- OUTPUT: 方向不跑偏

口播精要:"不会马上动手,而是先反过来问你 —— 这东西给谁用、想解决什么问题、有没有特殊限制。一轮问下来,你自己的思路先清楚了,它再开始干活,方向基本不会跑偏。"

适用:需求尚是「脑子里一个想法直接跟 AI 说『帮我做一个 XX』」时,**强制 SPEC-FIRST**。

### Skill 02 · SUMMARIZE(Process 02-06)

> **几十秒嚼碎信息喂给 AI**

三步:
1. **网页视频播客 PDF** —— 信息源穷举
2. **几十秒抓核心观点** —— 抓要点
3. **拿重点指挥 AI** —— 重点回流

三段式:
- INPUT: 任意格式素材
- MOTION: 抓要点 + 提数据
- OUTPUT: 可用信息

口播精要:"信息都锁在各种地方 —— 网页、视频、播客、PDF,你自己看一遍就要 40 分钟。Summarize 不管什么格式丢进去,几十秒抓出核心观点和关键数据,你拿着这些重点再去指挥 AI 干活,效果完全不一样。"

适用:喂 AI 前的资料预处理,**先把 40 分钟阅读压缩成 30 秒摘要**再下指令。

### Skill 03 · PROMPT OPTIMIZER(Index 03-06)

> **模糊表达变成清晰任务**

三步:
1. **优化提示词** —— 不是凭感觉
2. **对比优化前后结果** —— 直接对比输出
3. **换个问法差一档** —— 同样事换问法

三段式:
- INPUT: 模糊表达
- MOTION: 对比优化
- OUTPUT: 清晰任务

口播精要:"很多人觉得 AI 不稳定,一会儿好一会儿差,其实问题往往出在你给他的第一句话上。这个 Skill 帮你优化提示词,把模糊表达变成清晰任务,而且不是靠感觉调的,他会直接对比优化前后的输出结果,让你看到差在哪。同样一件事换一种问法,结果能差一个档次。"

适用:发现 AI 输出不稳定时,**不要改模型,先改问法** —— PROMPT OPTIMIZER 强制把"换问法"结构化。

### Skill 04 · SHOW OPTIONS(Feature 04-06)

> **选择比生成更高效**

三步:
1. **先摆出不同方向** —— 风格 A / 风格 B 平行给出
2. **挑一个最接近的** —— 人在回路挑
3. **再往下细化** —— 锁定后再生成细节

三段式:
- INPUT: 展示需求
- MOTION: 摆方向供挑选
- OUTPUT: 少改几轮

口播精要:"做 PPT 或者展示内容的时候,你是不是习惯让 AI 直接给你一个最终版?但你拿到手一看不满意,又说不清哪里不对,来回改好几轮。Show Options 换了一个思路 —— 他不直接给你答案,而是先把不同方向摆出来,风格 A 是这样的,风格 B 是那样的,你挑一个最接近的再往下细化。**选择比生成更高效**。"

适用:审美/创意类输出,**先要候选再要终稿**,把"凭感觉改"变成"挑出来"。

### Skill 05 · UI ROUTER(Process 05-06)

> **先判断场景,再分给对应 Skill**

三步:
1. **问给谁看什么场景** —— 受众 + 场景分类
2. **自动分给对应 Skill** —— 路由分派
3. **落地页 / 后台 / H5 都能出** —— 多端产出

三段式:
- INPUT: 页面设计需求
- MOTION: 判断 + 自动分派
- OUTPUT: 可演示页面

口播精要(比帧更详细):
- 后面接了一串 UI Skill(方向的、视觉审美的、页面一致性的、规则检查的)
- **关键不是这些工具本身,而是我在前面加了一层判断**
- 他不会上来就画页面,而是先问你:给谁看、什么设备、什么场景(要快速出活 / 还是做成作品)
- 判断清楚之后,自动把任务分给对应的 Skill 去执行
- 落地页、后台页面、H5 活动页都是这么一步步出来的

适用:**所有多 Skill 体系的入口**,本质上是个 routing/decision 节点 —— 取代"用哪个 Skill"的反复思考。

## 关键洞察(从口播提炼)

### 1. Skill 的「二八分组」

视频明确给出 **5 选 2 的功能分组**:

| 分组 | 涵盖 Skill | 任务 |
|---|---|---|
| **说清楚**(前 3) | SPEC-FIRST / SUMMARIZE / PROMPT OPTIMIZER | 把你的需求/资料/表达**结构化** |
| **做到位**(后 2) | SHOW OPTIONS / UI ROUTER | 把 AI 输出**精修**和**路由**到正确场景 |

口播原句:"**前三个帮你把事情说清楚,后两个帮 AI 把结果做好**"。

### 2. 三段式 = Skill 描述模板

每个 Skill 强制按 `INPUT → MOTION → OUTPUT` 三段呈现,可作为**设计自己 Skill 时的描述骨架** —— 让 Skill 既有「输入契约」「执行逻辑」「输出产物」三段语义。

### 3. UI ROUTER = 路由节点哲学

Skill 5 不是工具,是判断层。视频强调"**关键不是这些工具本身,而是我在前面加了一层判断**" —— 这是经典的 **agent router/decision node** 思想:在 LLM/Tool 之上加一个分类器,把任务路由到对应能力。

### 4. 通用金句

- "WorkBuddy 一直都有能力,真正拉开差距的,是你有没有给他一条清晰的工作流"
- "选择比生成更高效"
- "问题不是 AI 不行,是 你没给他一套干活的流程"

## 适用场景(对 BOSS)

- **设计自己 Skill 的方法论借鉴**:5 段式(澄清→摘要→优化→挑选→路由)+ INPUT/MOTION/OUTPUT 描述模板
- **评估当前 Skill 体系是否完整**:5 段哪一段缺?对应 Skill 是什么?
- **训练 LLM/Agent 时**:用这 5 段作为「任务前置分析」框架
- **运营/营销/品牌**:杂志风内容设计参考(Prism · AURORA EDITION 设计语言,角标、流程图、3 步编号)

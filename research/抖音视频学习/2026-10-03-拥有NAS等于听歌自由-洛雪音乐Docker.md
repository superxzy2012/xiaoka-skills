## ⚠️ 核查结论：视频演示的不是官方 Docker 部署

**这是本条最重要的发现。**

### 官方 `lyswhut/lx-music-desktop` 没有 Docker 部署

| 项 | 值 |
|---|---|
| 仓库 | `lyswhut/lx-music-desktop` |
| Stars | **54,122** |
| Forks | 7,047 |
| License | **Apache-2.0** ✅ |
| 语言 | TypeScript（**Electron 桌面应用**） |
| 创建 | 2019-08-14 |
| 最近 push | 2026-09-19 |
| 官网 | https://lyswhut.github.io/lx-music-doc/ |

官方文档站首页明确列出的是**桌面版**和**移动版**两个 GitHub 链接，
平台支持写的是「Linux、macOS、Windows 及 Android」，
并注明「**目前没有计划支持 iOS 和 HarmonyOS NEXT**」—— **全文无 Docker 字样**。

**结论：官方 LX Music 是 Electron 桌面软件，不提供 Docker 镜像。**
视频标题却叫「Docker 容器 / 洛雪音乐」，容易让人误以为是官方方案。

### 官方唯一的 Docker 组件是「数据同步服务」

`lyswhut/lx-music-sync-server` ★855 Apache-2.0（最近 push 2025-09-08），
官方描述：「运行在 Node.js 上的 LX Music 数据同步服务」。

**它只同步歌单/收藏列表，不提供音乐播放或下载。** 视频里能播歌，说明用的不是它。

### 视频实际用的是第三方 Web 音乐服务

搜索发现 NAS 圈实际在用的是这几个（都不是 LX Music 官方）：

| 项目 | 说明 | 许可 |
|---|---|---|
| `jia070310/lemon-muisc`（柠檬音乐） | **飞牛 NAS 原生 FPK**，不依赖 Docker；兼容洛雪音源脚本；v1.2.7 | MIT |
| `xhongc/music_tag_web` | Docker 镜像，搜刮/整理/播放，B站教程用其做飞牛部署 | 未核实 |
| `k1483162508/musicn` | Docker 镜像，支持咪咕/网易云/酷狗切换 | 未核实 |
| `wbsu2003/lx-music-sync-server` | 社区镜像，仅同步 | Apache-2.0 |

搜索「MelodyHub」在 GitHub 无匹配结果（可能已改名或非 GitHub 托管），
视频画面 OCR 也没能读出镜像名，故**无法确认视频用的具体镜像**。

## ⚠️ 版权与合规提醒

**这是本条最需要留意的地方。**

洛雪音乐的设计初衷（官方原话）：
> 本项目开发的初衷仅是为了对新技术的学习与研究，因此软件直至停止维护都将会一直保持纯净

它本身是**音乐查找工具**，配合**自定义音源脚本**访问第三方音乐平台的接口。
一旦用于**下载保存整曲**，就涉及：

1. **音源脚本本身可能侵权** —— 各平台接口均已加强反爬与版权管控
2. **AGPL 之外的额外风险** —— 用它下载的音频内容不因工具开源而获得授权
3. **平台账号风险** —— 音源脚本通常需要登录 Cookie，账号可能被风控

视频作者标题写「且看且珍惜」是明示风险。**商用、公开分发或分享下载内容前必须评估。**

## 💡 给 BOSS 的实际建议

本机是 Linux（Intel N100 四核），飞牛 NAS 是另一台机器。**若要装，建议路径**：

1. **先试 `lemon-muisc`（柠檬音乐）** —— MIT 许可、飞牛原生 FPK 不吃 Docker 资源、
   明确兼容洛雪音源，比 Docker 方案干净
2. **明确需求**：只是「跨设备同步歌单」→ 官方 `lx-music-sync-server` 就够
3. **不要**照抄视频里的镜像名 —— 视频画面 OCR 读不出，社区镜像也常挂马

# 让Codex零成本具备生图生视频的能力 通过构建Skill

> [!abstract] 摘要
> Codex++ 是开源协议转换层。叶秋的方法是在 Codex++ 里接入 agnes-ai 的大语言模型（agnes-2.5-flash），然后通过一个 Skill 调度 agnes image 2.0 / video 2.0 模型，让 Codex 在不花 token 的情况下生成图片和视频。

## 核心结论

1. **Codex++ 是开源的**：GitHub 仓库 `BigPizzaV3/CodexPlusPlus/releases/latest`，可以直接部署替代 CC Switch。
2. **整体链路**：Codex → Codex++ → agnes-ai 大语言模型 → Skill 调度 agnes 生图/生视频模型。
3. **Codex 本身只接大语言模型**，生图/生视频能力靠 **Skill** 完成调度。
4. **agnes-ai 平台有每日免费额度**，先注册拿 API Key 即可使用。
5. **关键坑点**：创建图片/视频时，**不要直接选 `agnes-image-*` 或 `agnes-video-*` 模型，仍要选大语言模型**（如 `agnes-2.5-flash`），由它来调用 Skill。

## 准备工作

1. **安装 Codex++**
   - GitHub: https://github.com/BigPizzaV3/CodexPlusPlus/releases/latest
   - 知识星球原帖补充：必须**从 Codex++ 进入 Codex**，否则模型下拉框不会出现 Image/Video。

2. **获取 agnes-ai API Key**
   - 访问 https://platform.agnes-ai.com/
   - 注册账号（邮箱 / Google / GitHub）
   - 创建新密钥（少量每日免费额度）

3. **Codex++ 中配置大语言模型**
   - 视频里使用：`agnes-2.5-flash`
   - 知识星球帖子里写：`agnes-2.0-flash`
   - 模型下拉框会出现：`agnes-image-2.0-flash`、`agnes-image-2.1-flash`、`agnes-video-v2.0` 等

## 操作步骤

### 方式一：直接安装现成 Skill

```bash
npx skills add Yacey/agnes-ai-generation-skill --all
```

将下载好的 Skill 放入 **Codex 的 skill 目录**，然后**重启 Codex** 才生效。

### 方式二：让 Codex 自动构建 Skill（视频中演示）

1. 从 **Codex++** 打开 Codex。
2. 在 Codex 中选择项目目录里的 **skills 目录**（Skill 创建后会自动存在这里，方便后续调用）。
3. 在输入框中粘贴提示词：

```text
我想要使用 agnes image 2.0 模型去生成图片，访问它的 API 文档 https://agnes-ai.com/doc/agnes-image-20-flash，并将它打包成一份 skill。
```

4. 等待 Codex 自动构建 Skill。
5. 构建完成后，Codex 的模型下拉框里会多出 `Image`、`Video` 相关模型。
6. 把获取到的 **agnes-ai API Key** 配置给 Skill（最好在构建时就传入，视频中是生图后才补传，不影响使用）。

## 使用验证

1. 从 Codex++ 打开 Codex 对话框。
2. 选择大语言模型，例如 `agnes-2.5-flash`（**不是 `agnes-img`**）。
3. 输入：
   - 生图：`生成一只蓝色的狗狗在沙发上的图片`
   - 生视频：`这只小狗从沙发上跳下来的视频`
4. 生成的图片/视频会保存到本地，并在对话中给出可点击的 URL。

## 关键坑点

| 坑点 | 正确做法 |
|------|---------|
| 不通过 Codex++ 进入 Codex | 必须从 Codex++ 打开 Codex，否则技能不生效 |
| 直接选 `agnes-image-*` / `agnes-video-*` 模型 | 仍选大语言模型（`agnes-2.5-flash`），由它通过 Skill 调度 |
| API Key 没传给 Skill | 在构建 Skill 时就把 Key 配置进去 |
| Skill 没放对目录 | 放到 Codex 项目目录下的 `skills` 文件夹 |

## 与你项目的关系

- 这提供了一条 **0-token 让 Codex 具备多模态生成能力** 的路线。
- 核心依赖是 **Codex++ + agnes-ai 免费额度**，比 CC Switch 更可能支持图片/视频相关能力（因为 Codex++ 是叶秋专门维护的 Codex 适配层）。
- 如果你想让 Codex 能**粘贴图片读图**（而不是生图），Codex++ 同样可能解决，因为它的上游可以换成支持视觉的模型，而且它是开源的，协议转换层可以 inspected / patched。

## 口播 / 转录全文

兄弟们，大家有没有想过在 Codex 里面给它赋予生图和生视频的能力，同时还免费，在很多人那里可能听起来像天方夜谭。

但是我的技术逻辑是这样的：因为我们的 Codex++ 它只能接入大语言模型，我们需要用一个 Skill 去完成对于生图生视频模型的调度。这种生图生视频的能力结合到我们的 Codex 之后，其实大家可以充分发挥自己的想象力，价值还是非常大的。

大家记住从 Codex++ 这里进来。如果你不从 Codex++ 这里的话，你是用不了这个。

然后我们在 Codex 的项目目录这里，我们选择 Codex 的 Skill 这个目录。主要是便于等会它把 Skill 创建好之后，它会自动存在这个目录里面，方便我们后面去调用它。

然后把这一段提示词给复制进去就可以了。接下来我们只需要等待一下，它自动会帮我们把 Skill 给构建完成。

那神奇的地方就来了。当它构建好 Skill 之后，我们发现我们的 Codex 的模型下拉框里面多了一些模型，比如说像 Image、Video。不知道大家还记不记得，我们之前在演示添加这个 Image 或者 Video 的时候，它会报错。但是创建了这个 Skill 之后，它自动就出现了。

Skill 是已经创建好了，但是到底用了怎么样，我们来测试一下。那么下一个坑点又来了。当我们在创建图片或者是创建视频的时候，我们不要选择 Video 或者 Image 的模型，而是还是选择大语言模型。这里我让它给我生成一张蓝色的小狗在沙发上的图片。

这上面已经清晰地告诉我们了：Image 的模型都是通过我们的大语言模型调度出来的。然后还有一点其实应该在 Skill 构建的时候，我们就应该把 API Key 传递给它。然后这里的话是我在生图之后才给它补上去了。下面这个包装其实没什么影响，大家不用担心，它只是影响我们展示。这里的 Image 其实已经保存到我们本地了。

我们大家看看，免费的模型有这种效果已经非常不错了。这个其实跟我想象的是非常接近的。那我的目标其实还是想生成一段视频出来。但是生成出来的效果到底怎么样，其实我也不知道。因为就目前而言，AI 界的最贵最消耗算力的其实就是生视频。

它视频已经创建成功了，并且保存在本地。我们打开来看看。感觉这个效果已经非常好了，我觉得跟我们付费的效果差不多。因为这个还没有加入一些复杂的提示词，我们只是把功能给它跑通。

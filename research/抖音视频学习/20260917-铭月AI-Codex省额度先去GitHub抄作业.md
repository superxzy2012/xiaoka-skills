# 你用 Codex 为什么额度掉那么快？

> **一句话核心**：用 Codex 最费额度的用法是「第一句话就让它写代码」；最省的用法是先让它去 GitHub「抄作业」——调研现成开源项目、给出复用/改造/从零开发的判断和最简 MVP，**等你确认方案后再动手写**。

## 方法拆解（口播 + 画面 prompt OCR 交叉验证）

1. **错误开场**：「很多人第一句话就是直接开始（写代码）」→ 大量 token 耗在 Codex 重新发明已有的轮子上。
2. **正确开场**：你想做的东西 GitHub 上大概率已经有人做过——**先别写代码，去 GitHub 抄作业**。
3. **让 Codex 带着检查清单做尽调**（画面实证的完整 prompt，见下节），产出三选一判断：直接使用 / 基于现有项目改造 / 从零开发，并附最简 MVP 方案。
4. **确认方案后再开发**——把 token 花在确定性高的实现上，而不是探索和返工上。

## 画面中给出的完整 Prompt（OCR 实证，可直接复用）

```
我要做一个【帮助ADHD朋友的产品】
先不要写代码，请在 GitHub 中寻找适合直接使用或二次开发的开源项目
请检查：最近提交和版本发布时间、Star 与社区活跃度、开源许可证、
依赖维护情况、测试是否能够运行、部署难度、可复用功能以及技术栈匹配度
最后比较这些项目，并告诉我应该直接使用、基于现有项目改造，
还是从零开发，请同时给出最简单的 MVP 方案，等我确认后再开始
```

8 项尽调维度：**提交活跃度 / 版本发布时间 / Star 与社区 / 开源许可证 / 依赖维护 / 测试可运行性 / 部署难度 / 可复用功能与技术栈匹配度**。

## 对 ANC / AI Factory 的价值（Friday 评）

- 与 AI Factory 既定原则 **Search → Reuse → Extend → Build only when necessary** 完全同构，这是外部独立佐证：先复用再自建同时省 token、省时间、降风险。
- 可直接固化进 CAP-001 Codex Pipeline 的任务模板：任何新编码任务的**第一拍必须是开源尽调 + 三选一决策单**，禁止直接进入实现。
- 8 项检查清单可作为 CAP 复用评估的默认字段（尤其「许可证」「测试能否运行」「部署难度」是我们过往评估中偏弱的项）。
- 额度视角补充：Codex/Ark 等按用量计费时，方案阶段的返工是最大隐性成本；「确认方案再开发」= 最便宜的质量门禁。

> 兄弟们，我们终于可以零 Token 使用 WorkBuddy 了。其实它的原理就是利用我们的本地大模型作为我们的意图理解，然后用我们的 AFS 和 Trim 作为数据处理和调用工具的引擎，并且把它转换成标准的 OpenAI 格式的 API。当我们的 WorkBuddy 接入这个 OpenAI 格式的 API 之后，驱动连接器，最后完成整个任务。
>
> 我相信一定会有小部分人还是觉得很惊讶。那么我们把完整的测试过程展示给大家。

> 首先打开我们的 AFS，然后在我们的模型管理之中添加模型。我这里添加的是 DeepSeek。添加完之后，点击下一步。然后这里我们只需要像日常登录我们的网页端跟账号一样，登录一下，这个操作就已经完成了，就这么简单。
>
> 然后在账号这里，我们可以看到一个 desecret 帮好在里面了。然后还需要带来我们的零 Token 技术神器 Trim。这里只需要在里面输入一行命令就可以完成，点击回车，自动会弹出一个 UI 界面。这里只需要做一些简单的配置，然后我们就拥有了一个零 Token 的、是一个无限使用。
>
> 接下来打开我们的 WorkBuddy，在设置模型中选择自定义模型。由于刚才我们把零 Token 的服务端口已经打开了，那么只需要按照我这个来填写一下对应的接口地址和 API Key 就可以了。模型名称我们从 AFS 的模型管理中复制下来，点击保存。这时候我们可以看到 WorkBuddy 的模型列表中已经有了 DeepSeek 的两个最新的模型。

## 💡 关键要点

1. **零 Token 的本质**：不是不调用大模型，而是把**本地大模型**包装成 OpenAI 兼容的 API，让 WorkBuddy 走这个 API 调用工具，全程不消耗云端 Token。
2. **三件套**：AFS（模型管理）+ Trim（工具引擎）+ WorkBuddy（调用方），缺一不可。
3. **AFS 配置**：在模型管理里添加 DeepSeek → 登录网页端账号 → Trim 输入一行命令 → 弹出 UI 配置 → 完成。
4. **WorkBuddy 接入**：设置 → 自定义模型 → 填接口地址 + API Key（从 AFS 复制）→ 保存 → 模型列表出现 DeepSeek。
5. **连接器是关键**：WorkBuddy 是独立封装软件，必须通过 MCP 等连接器才能驱动它完成任务。演示中用自定义 MCP + 浏览器分析工具。
6. **实测验证**：把 WorkBuddy 介绍页丢给它，自动总结成表格 + 流程图，证明整套链路跑通。

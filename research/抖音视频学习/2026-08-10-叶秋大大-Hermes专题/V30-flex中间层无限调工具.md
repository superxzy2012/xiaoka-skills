## 痛点与方案

- 网页大模型转 API 后，以前靠**提示词注入**让它具备调用能力，但**不够稳定**
- 解法：在**客户端和 Hermes 之间加一个 flex 中间层**，对数据做处理后让大模型稳定调用，并加入**流式处理**，使多人在对话中仍能执行任务

## 实操（已脚本化）

1. 打开「网页大模型转 API」工具
2. 在终端执行脚本：把 Hermes **接入中转网关**（脚本已封装，避免手动出错）
3. 重启中转网关
4. 新窗口启动 Hermes，问「你是谁」确认已切到网页大模型中转网关
5. 遇到 **HTTP 500 API 网关无响应** → 排查发现**代理没打开** → 启动代理后正常
6. 确认 Base URL 是本地网关（由网页转换而来，**不费 Token**），非通用 API
7. 实测：调本地工具查文件 ✅ → 建新文件「Zero Token Hermes」✅ → 总结方法生成 MD 存放 ✅

## 与你项目的关系

- 这篇是 V21/V22/V24 的**进阶版**：当免费模型的工具调用不稳定时，用「中间层 + 流式处理」兜底，支持多对话并发。
- 对 WorkBuddy：若 WorkBuddy 接免费网页模型后工具调用偶发失败，可考虑在 WorkBuddy 与转 API 服务间加一层中间处理（类似 flex）提升稳定性。
- **排错经验可复用**：接网关后报 HTTP 500，先查「代理是否开启」，这是高频坑。

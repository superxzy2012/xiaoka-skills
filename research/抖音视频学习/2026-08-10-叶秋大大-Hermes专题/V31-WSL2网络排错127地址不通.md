## 问题场景

正常情况：开代理 → 填本地地址 + 端口 → 接 Hermes 就能用。
但小部分人接进去**连不上**。排查发现他们的网络环境是：

- Hermes 跑在 **Windows 电脑的 WSL2** 环境里
- 客户端是 **EXE 文件**，只能放在 **Windows 主机**里（客户端也有 Linux / Mac 版）

这种情况下，若还按教程填 **`127.0.0.1`**，肯定不通（WSL2 和 Windows 主机网络隔离）。

## 解决

1. 进入 **WSL2 环境**，在终端输入一条命令，获取 **Windows 主机的服务器地址**
2. 用这个地址**替换之前的 `127.0.0.1`**
3. 重新进 Hermes 配 API，把 **Base URL** 换成新地址即可接通

## 与你项目的关系

- 你本身是 Mac，这条坑你大概率不会踩；但 **OPC 一人公司**若用 Windows + WSL2 部署 Hermes / 转 API 服务，这是高频排错点，先存着。
- 核心原则：**跨虚拟化边界（WSL2 ↔ Windows 主机、容器 ↔ 宿主机）时，`127.0.0.1` 指的不是同一个网络命名空间**，要用对方真实可达的地址。
- 映射到 WorkBuddy：若 WorkBuddy 接本地转 API 服务，确保两者在同一网络命名空间，或用宿主机真实 IP。

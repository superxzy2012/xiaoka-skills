# 四个项目组合成个人AI工作站：王炸方案

> [!abstract] 摘要
> AI樟榆树提出：把 **Semantica（长期记忆）＋ holaOS（交互与应用）＋ Herdr（多Agent运行）＋ OMLX（本地推理）** 四个开源/自研项目组合起来，可形成一套「本地优先、拥有长期记忆、可同时运行多个 Agent、能操作浏览器和外部应用」的个人 AI 工作站。核心是**双控制面、单一事实层**架构。

## 四个项目与层级职责

| 层级 | 项目 | 核心职责 | 对应关系 |
|---|---|---|---|
| 交互与应用层 | **holaOS** | 用户界面、浏览器、文件、应用连接、自动化 | — |
| 多 Agent 运行层 | **Herdr** | 同时运行和监控 Codex、Claude Code 等终端 Agent | `ogulcancelik/herdr` |
| 长期知识层 | **Semantica** | 知识图谱、语义记忆、决策记录、来源追踪 | AI Memory 类项目 Semantica |
| 模型推理层 | **OMLX** | 在 Apple Silicon Mac 上运行本地模型 | `jundot/oMLX` |

## 四者组合能解决什么

1. **Agent 每次启动都失忆** → Semantica 保存事实、关系、决策和历史先例；新 Agent 启动后经 MCP 查询「采用什么架构 / 为什么选这个数据库 / 哪些方案试过失败 / 当前未解问题 / 某决定是谁在何种证据下做出」。
2. **多个 Agent 各自为政** → Herdr 负责同时运行它们，Semantica 负责共享长期知识，holaOS 负责共享工具、文件与应用（A 调研、B 改码、C 测试、D 审安全，共同事实与决策归一）。
3. **数据隐私和模型成本** → OMLX 承担分类、摘要、信息抽取、Embedding、Reranking、常规代码辅助；只有困难任务才交云模型（本地优先 ≠ 绝对离线）。
4. **AI 只能聊天、不能完成工作** → holaOS 把 Agent 接到浏览器、邮件、文件、GitHub、协作工具、自动化任务，让输出进入真实工作系统。

## 推荐架构：双控制面、单一事实层（第三种）

- **holaOS**：日常任务、文件、浏览器、工具、审批
- **Herdr**：开发、测试、多 Agent、后台服务
- **Semantica**：唯一长期知识与审计层
- **OMLX**：默认本地推理层

关键约束：
- holaOS 自带记忆只保存短期会话和界面状态，**不作为长期事实源**
- Semantica 只接收**经过分类、带来源**的数据
- OMLX 失败时允许切换云模型，但必须留下**模型路由记录**
- Herdr 管理进程，不承担知识存储
- 所有真实外部写操作都经过**批准闸门**
- 第一阶段只在一个独立沙盒项目中运行

> 另两种被否方案：① holaOS 中心型（受 holaOS 集成边界影响大）；② Herdr 中心型（日常操作不直观）。

## 核心数据流

任务输入 → 权限与风险分类 → 检索 **Semantica** 中相关事实/决策/历史先例 → 选择执行路径：
- 普通工作：holaOS Agent 直接执行
- 编程或长任务：交给 Herdr 中的 Agent
- 高风险操作：暂停并等待人工批准

→ **OMLX** 本地模型推理 → 调用文件/浏览器/MCP/其他工具 → 验证执行结果 → 生成审计事件 → 候选记忆提取 → **通过记忆写入闸门后进入 Semantica**。

## 目标模式（产品化）

不是简单集成四个项目，而是交付一套：
- 通用、可分发、开箱即用的 **Mac AI 工作操作系统**
- 统一安装、初始化、运行和操作体验
- 具备长期记忆、端到端审计、多 Agent 并行和真实工具操作
- 本地优先、安全默认、组件可替换、故障可恢复
- 能让陌生用户独立部署并完成关键任务（含文档、实现、自动化部署、契约测试、安全与恢复测试、真实工具闭环、操作手册、陌生用户人工验收）

## 对你项目（OPC 一人公司 + agent 蜂群）的价值映射

这篇正好命中 BOSS 当前方向，可直接当个人 AI 工作台架构蓝本：

- **长期知识层 Semantica** ≈ 小丽的 `agent-memory-store`（端口 8768，SQLite+TTL 跨 Agent 共享记忆）
- **多 Agent 运行层 Herdr** ≈ 小丽的 CEO 管理栈（`ceo-delegation` / `multi-agent-cn` 派发子 Agent、监控状态）
- **本地推理层 OMLX** ≈ BOSS 当前优先项「0 token 方法 / 本地小模型」（免费网页端模型转标准 API 接 Hermes）
- **交互与应用层 holaOS** ≈ 把 Agent 真正接到浏览器/文件/GitHub/协作工具，而非停在聊天文本——正是「可分发产品」的落点
- **批准闸门 + 单一事实层** 与 BOSS 的密钥安全铁律、外部写操作先请示原则一致，可直接复用
- **第一阶段只在独立沙盒跑** 也呼应了诸葛亮那台局域 Windows 上 Hermes 的隔离部署思路

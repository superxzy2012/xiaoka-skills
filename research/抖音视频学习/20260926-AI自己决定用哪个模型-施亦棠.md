# AI自己决定用哪个模型 · 国外发射演示的一套 AI agent 自主路由系统

> [!abstract] 摘要
> 这是一条录屏演示视频（作者：施亦棠），展示一套 AI coding agent 的**自主模型路由/决策系统**。核心组件叫 **Jev**（Jev decision layer / 决策层）：当 agent 接到一个编程任务时，**不是人写死「这一步用哪个模型」，而是 Jev 根据每一步的上下文自动打分、从候选模型池里挑一个并用多大算力**去执行，全程有延迟、耗时占比、置信度可视化。视频用一个真实 bug 修复任务串起整条链路。

## 要点
- **一句话定位**：所谓「AI 自己决定用哪个模型」，指的是 agent 框架里多了一层**决策/路由层（Jev）**，它替代人工写死的 if-else 路由，按步骤动态选模型+工具+effort。
- **决策流（核心机制，OCR 实证）**：
  - Host（执行层）先准备好 `route options`（候选：多个模型 × 多个 effort 档）；
  - Jev 对每个选项打 **p=置信度**，然后 `choose` 或 `abstain`（弃权）；
  - 带 `Host checks`：校验「工具在已授权 bundle 内 / 工具定义当前有效 / 路由仍当前 / effort 被该模型支持」后才真正执行。
- **候选模型池（OCR 实证）**：`opus-5.5`（low/medium/high）、`sonnet-5:medium`、`haiku-4.5:Low` 等，界面实时显示 `LIVE RANKING` 与各选项得分。
- **effort 自适应（卖点之一）**：同一模型有 low/medium/high 算力档。演示中第一次 patch 后 `cargo test` **失败**（37 passed, 1 failed），Jev 把 effort 从 medium **升到 high** 做第二次修补，最终 `38 passed, 0 failed`。
- **小模型够用时主动降级省成本**：`Jev #14 chose haiku-4.5:low to write the summary. Small model is enough.`；`Jev #13 chose drop-tool-output` 丢弃工具输出省 token；上下文自动 `compact`（152.3k → 37.6K tokens）。
- **完整任务闭环（OCR 实证的时间线）**：
  - 任务：`Fix escaped quotes in the tokenizer`（修分词器里转义引号的 bug，Rust 项目 `src/Lexer/tokenize.rs`）；
  - 链路：`inspect → grep/read_file 定位 → edit_file 改 → run_tests(cargo test -p lexer) → 失败 → 升 effort → 二次 edit_file → 测试通过 → answer`；
  - 决策延迟可视化：单步 Jev 决策约 57–88 ms，整趟 22 次决策累计约 1641 ms（界面 `decisions • X ms total`）。
- **演示的「可观测性」卖点**：界面有 `Query timing`、`Jev time and share`（决策耗时占比）、`Context and model`、`Timeline by lane`、`Decision stream` 等面板，把「AI 怎么选的」完全摊开给人看。

## 关键信息
- **人物/主体**：抖音作者「施亦棠」；视频演示的是其「国外发射」的一套 agent 系统（具体产品名视频未给，核心模块叫 **Jev**）。
- **技术栈线索（OCR 实证）**：Rust（`cargo test -p lexer`、`src/Lexer/tokenize.rs`）；涉及模型 Opus 5.5 / sonnet-5 / haiku-4.5（即 Anthropic + OpenAI 系模型的路由编排）。
- **核心方法**：把「模型选择」从硬编码路由改为**由一层决策模型按置信度动态路由**，并配套 effort 自适应、小模型降级、上下文压缩、工具授权校验。
- **对我们有什么用（BA 视角）**：这是 agent 架构里「router / orchestrator」范式的活样例，可对标我们 ANC 的 CEO 委派与多 agent 调度思路——区别在于它把「选哪个执行者/用多大算力」也自动化了。可作为「AI 自主决策路由」的学习素材入库。

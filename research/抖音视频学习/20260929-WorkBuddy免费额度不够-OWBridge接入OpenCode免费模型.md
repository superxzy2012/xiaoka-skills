# WorkBuddy 免费额度不够？OWBridge 把 OpenCode 免费模型接进 WorkBuddy

> [!abstract] 摘要
> 娄老师针对 WorkBuddy 免费模型只有 2 个、其余都要积分的问题，自研了 **OWBridge**：自动检测 **OpenCode** 里的免费模型（实测 8 个，含推理/图片/工具调用能力），一键导入 WorkBuddy；**免主侧（无需自己的 API Key）、全自动、每日刷新额度**。适合速度要求不高、不做 coding 的日常任务。

## 核心信息

| 项 | 内容 |
|---|---|
| 项目名 | **OWBridge** |
| 解决的问题 | WorkBuddy 免费模型仅 2 个，其余需积分 |
| 模型来源 | OpenCode 内的免费模型 |
| 实测可用数 | **8 个** |
| 三大优点 | ① 免主侧（无需自有 API Key）② 全自动检测+导入 ③ 每天刷新额度 |
| 局限 | 免费模型速度不太快；不适合 coding 任务；日常办公足够 |
| 检测字段 | 模型名、响应耗时、能力标签 |

## 模型标签含义（重点）

| 标签 | 含义 |
|---|---|
| `推理` | 支持推理类任务 |
| `图片` | 支持图片输入、可读图（多模态） |
| `可用` | 可调用工具，能完成复杂工作 |
| `可用·仅对话` | 只能对话，**用不了工具** |

## 演示中出现的模型（来自 OpenCode）

- OC · Big Pickle（推理 / 可用，响应约 5.2s）
- OC · Ling 3.0 Flash Fin Free（推理 / 可用，响应约 1.6s）
- OC · LongCat 2.5 Preview Free（推理 / 图片，响应约 4.8s）
- 其余共 8 个，自动出现在 WorkBuddy 模型列表中

## 工作流程（视频演示）

1. 打开 WorkBuddy → 免费模型只有 2 个，其余都要积分。
2. 打开 OWBridge → 自动检测 OpenCode 免费模型，逐个显示耗时与标签。
3. 检测出 8 个可用模型 → 一键「导入 WorkBuddy」。
4. 回到 WorkBuddy → 模型列表出现 8 个新免费模型。
5. 用 WorkBuddy 自带工作台任务实测 → 能正常完成日常工作。

## 要点

- OWBridge 的价值是**搬运免费额度**：把 OpenCode 每日刷新的免费模型桥接给 WorkBuddy 用。
- 区分「可用」与「可用·仅对话」是关键——后者无法执行 agent/工具类任务。
- 作者定位明确：**非 coding、非高速需求**的日常任务场景。
- 对 BOSS 的潜在用途：WorkBuddy 积分紧张时可作为免费模型补充通道；需要核实 OWBridge 是否开源/可获取（视频未给出仓库地址，**未验证**）。

## 口播全文

> 我可包袋（WorkBuddy）积分不够用怎么办？我做了一个项目叫做 OWBridge，它是把 OpenCode 里的免费模型交给我可包袋使用。它优点很多，主要就是免主侧、然后全自动，而且每天都会刷新额度。
>
> 我们打开我可包袋去看它那个模型的话，你会发现现在免费的其实只有两个，然后其余的或多或少都需要积分。然后我们打开我的 OWBridge，会看到它会自动地检测 OpenCode 里边的这个免费模型。看它已经找到了第一个，然后很快就会把所有的免费模型检测出来，而且它会检测一个耗时。
>
> 同时大家注意这里面的标签，它有这个推理、然后可用，然后还有图片，我给大家说一下这是什么意思。推理的意思就是说它支持这种推理；然后图片的话是你可以给它发图片，它能够读懂；然后「可用·仅对话」意思就是用不了工具；「可用」就是它可以调用工具，可以完成复杂的工作。
>
> 现在应该是有 8 个免费模型可以用，它会自动地放到我可包袋里。我们现在再打开我可包袋，你看，里边有了 8 个不同的这个免费模型。我们随便选一个，然后用我可包袋里边自带的这种工作台任务测试一下。
>
> 我目前用着应该还算可以嘛，但是因为免费模型嘛，相对来讲它的速度不是很快，属于说是你对速度要求不是那么高、而且不用它去做 coding 任务的话，日常的这些工作我觉得是足够了。然后大家看，这个基本上就已经做完了，它是能够很好地完成我可包袋里边的一些工作的。

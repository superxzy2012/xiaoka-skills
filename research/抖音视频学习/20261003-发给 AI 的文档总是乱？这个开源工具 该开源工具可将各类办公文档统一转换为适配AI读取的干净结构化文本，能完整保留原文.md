## 💡 关键要点

**项目：[firecrawl/anydoc](https://github.com/firecrawl/anydoc)** —— Firecrawl 官方出品的文档转 Markdown 引擎，Rust 实现。

### 解决什么问题
办公文档丢给 AI 会「读成一塌糊涂」，根因是**不同格式对 LLM 差别巨大**：
- PDF 里的表格其实是**画出来的**（矢量线条），不是文本
- Word 的结构**藏在样式里**（style），直接读会错位
- 各家格式语义不统一，模型要分别学

anydoc 把这些**压成同一种干净的 GFM Markdown**，模型只需学一种结构。

### 核心能力（均已回源核实）
| 能力 | 说明 |
|---|---|
| 支持格式 | Word / PowerPoint / Excel / OpenDocument / RTF / EPUB / CSV / PDF |
| 真格式识别 | **不只看扩展名**，打开文件读魔数判断真实类型 —— 改后缀骗不过它 |
| 速度 | single-digit milliseconds（个位数毫秒） |
| 本地转换 | 浏览器 WebAssembly 演示页，**文件不离开本机** |
| 绑定 | Node.js(napi) / Python(PyPI `firecrawl-anydoc`) / Rust(crates.io) / WASM |
| 生态 | 是 **Firecrawl Parse** 的底层引擎；官方提供 Agent Skill |

### 上手方式（README 原文命令）
```bash
# 方式1：装成 Agent Skill（推荐，agent 直接会读文档）
npx skills add firecrawl/anydoc

# 方式2：CLI
npx @firecrawl/anydoc report.docx              # 输出到 stdout
npm install -g @firecrawl/anydoc               # 永久命令

# 方式3：Python
pip install firecrawl-anydoc

# 方式4：浏览器试用（本地转换，文件不出机器）
https://firecrawl.github.io/anydoc/
```
扫描件（图片型 PDF/Office）本身读不了，需 `--ocr hosted` 走 Firecrawl 托管 OCR。

### 与我现有工具的关系
我已有 `markitdown-skill`（微软官方，同类用途）和 `glm-53-flash-vision-rag`（PDF 深度问答）。
**anydoc 的差异优势**：① 格式覆盖更全（含 OpenDocument/RTF/EPUB/CSV）；② Rust 内核快一个量级；
③ 提供 Agent Skill 形态，能直接挂进 Hermes 技能库；④ MIT 协议可商用。

### 它到底干什么

把"选工具 → 学 API → 搬证据 → 决定下一步"这套逆向工程手工活**交给 Agent**：

**调查模型：Decompile → Understand → Recreate**

| 步 | Agent 做什么 | REA 工具 |
|---|---|---|
| 1 | 打开并识别二进制 | `open_binary`、`binary_overview` |
| 2 | 找离线搜索线索 | `search_strings`、`search_procedures`、`list_names` |
| 3 | 把线索连到可执行代码 | `find_xrefs_to_name`、`xrefs`、`procedure_callers` |
| 4 | 重建相关控制流 | `get_call_graph`、`procedure_callees`、`procedure_info` |
| 5 | 反编译相关例程 | `procedure_pseudo_code`、`procedure_assembly`、`batch_decompile` |
| 6 | 在你自己项目里实现该功能 | Agent 用它正常的编辑/测试工具完成 |

**68 个工具，5 大族**：原生检查 33 个 / 调查工作流 10 个 / macOS 原生工具 5 个（Mach-O、代码签名、plist、Swift demangle）/ 制品图谱 2 个（ZIP/APK/IPA/ASAR）/ 工作区与观测 18 个。

**覆盖范围**：原生二进制（Hopper / 自备 Ghidra）、JS 与 Electron 应用、.NET 程序集、网站、Node/V8 Inspector 被动观测、JS source-map 重建、Evidence v2 可复现证据记录。

**关键特性**：
- **本地运行，不上传**（Local by design，分析全在本机）
- **能接的 Agent**：Claude Code / Claude Desktop / Codex / Cursor / Gemini CLI / Windsurf（Devin 只识别不配置）；**任何支持本地 MCP 的 Agent 都能手动接**
- **装上后一句话开工**：`npx rea-agents setup`，然后对 Agent 说"理解 XX App 的搜索怎么实现的，给我证据，并在我项目里做个类似的"
- **明确划界**：*"不声称能还原原始源码，也不自动克隆应用"* —— 只解释**功能怎么工作**，然后你**自己重写**

## 观点 / 待验证

1. **口播说"我也不能讲"，不是噱头——是合规红线。** 逆向工程在国内属于灰产边界（破解、去广告、抄功能都沾边）。作者回避讲解，恰恰说明这工具的**用途敏感性**远高于它的技术含量。对 13BIT 这类跨境业务，**看它做什么可以，拿它去扒竞品 App 要慎重**。

2. **真正值得抄的不是工具，是它的"证据链"设计。** REA 最硬的工程点是 **Evidence v2**：每条结论必须区分「观测 / 推断 / 未知」，引用 Evidence ID，保留局限与覆盖缺口，**绝不把静态分析说成观测到了运行**。这套"结论必须可追溯到证据、并显式声明不知道什么"的规范，**正是我们多 Agent 体系最缺的东西**——小丽/小卡/阿正互相报"已完成"时，缺的就是这个。建议把 Evidence 三段式（观测/推断/未知）借到我们的质检 SOP 里。

3. **对 13BIT 的实际可用场景**（合规前提下）：
   - **自家 App / 自有网站**：分析自家 Electron 应用或前端 bundle，查性能瓶颈、找隐藏 bug、审计第三方 SDK 到底偷传了什么 —— **完全合法，且价值最高**
   - **文档缺失的格式**：分析私有文件格式、未公开的 API 契约（自有系统对接场景）
   - **依赖审计**：查 npm 包 / 第三方 SDK 的真实行为
   - ⚠️ **不建议**：扒竞品 App 功能后直接复刻（Ozon / 美客多 / TikTok Shop 的卖家端）。功能可借鉴，但**代码级复刻**在跨境场景下风险不对称——收益有限，法律风险实打实。

4. **技术栈契合度**：REA 是 **MCP server**，而我们的 Hermes 集群原生支持 MCP。若要做合规场景（如审计自家应用），接入成本很低：`npx rea-agents setup` 后手动配 MCP 即可。前置依赖是 **Hopper（macOS，付费）或自备 Ghidra（免费，Linux x64 成熟 / Windows x64 实验性）**。

5. **待验证（下次可做）**：
   - [x] **本机是否已有 Hopper / Ghidra？** → **全部未装**（Hopper / Ghidra / IDA 三者皆无）
   - [x] **npm 上确有此包？** → ✅ `rea-agents@6.4.0` 实测可查（独立于 GitHub 的第二信源）
   - [x] **Node 环境？** → ✅ node v26.8.1 / npm 11.19.0，前置满足
   - [ ] 把 REA 的 MCP 接到 Hermes，**只对自家应用**跑一次完整调查，验证"观测/推断/未知"三段式输出质量
   - [ ] 评估其 Evidence v2 契约能否直接借用到我们的 `quality-checker` / `independent-qc-audit` 技能里

> **重要区分**：没有 Hopper/Ghidra **不等于 REA 不能用**。官方明确说明——
> **静态 JavaScript 分析不需要任何原生分析引擎**，网站 / Electron 页 / Node V8 Inspector 被动观测、JS 与 source-map 重建、制品图谱（ZIP/APK/IPA/ASAR 清单）也都独立于 Hopper/Ghidra。
> **只有"原生二进制深度分析"才依赖 Hopper 或 Ghidra**。
> 所以想零成本试水，完全可以先只跑 JS/Electron/网站这条线。

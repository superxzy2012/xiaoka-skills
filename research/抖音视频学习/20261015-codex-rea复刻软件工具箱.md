# Codex + REA 复刻软件工具箱

> [!abstract] 摘要
> 视频用一个 Windows 桌面软件做示例，展示 REA 如何分析原生窗体、控件和初始化逻辑，并让 Codex 生成免账号的界面预览副本；进一步可把常用功能抽成 Codex Skill，或直接接入自己的工作台。可学习的是「软件功能 -> 业务流程 -> 自动化能力」的拆解方法，不能把它理解为鼓励破解、绕授权或规避付费。

## 要点
- REA 是面向 coding agent 的逆向工程 MCP，可分析二进制、应用结构、原生界面、运行时行为和调用关系。
- 视频里的流程是：先定位登录窗体和主窗体，再分析控件数量、初始化函数与数据依赖，最后生成只用于观察界面结构的本地预览副本。
- 画面显示示例程序中登录窗体约 52 个控件、主窗体约 1,432 个控件，REA 能辅助定位窗体初始化函数和后续反编译分析。
- 「登录改预览」的本质是绕过依赖账号数据的初始化路径，让主界面能在本地测试副本中显示；这适合兼容性研究、界面学习和自有系统设计，不应作为免登录使用他人软件的方法。
- 第一种复用方式是把某个高频模块抽离成 Codex Skill：输入目标、步骤、所需文件或页面，让 agent 按固定流程执行。
- 第二种复用方式是跳过单独 Skill，直接把能力嵌入已有工作台，成为内部工具链的一个功能。
- 电商场景里，软件本身不是核心壁垒；更值得复刻的是它沉淀的操作顺序、字段设计、判断规则和业务 SOP。
- 公开资料显示 REA 项目为 MIT License，GitHub 仓库是 `morluto/rea`，官网为 `https://rea.tools`；视频中说的 17 万 star 是录制时的口径，实时 star 数会变化。

## 可执行学习路径
1. 选一个自己有合法授权或允许分析的软件，只选一个高频功能，例如批量查词、刊登校验、订单分流或客服话术生成。
2. 用 REA 做静态观察：识别程序形态、主要窗体、控件、入口函数、依赖文件和网络边界。
3. 记录业务 SOP：用户点了什么、需要哪些输入、系统如何判断、产出什么字段、异常如何处理。
4. 不复用对方代码和素材，只重写实现逻辑；把规则沉淀为自己的需求文档、流程图和测试用例。
5. 用 Codex 先做成独立 Skill 或脚本，跑通单一闭环；稳定后再接入内部工作台。
6. 保留授权、隐私和数据安全边界：不绕过付费、不抓取越权数据、不在生产环境运行未经验证的修改副本。

## 合规边界
- 学习界面交互、分析自有软件、研究兼容性或安全问题，与破解他人商业软件是两回事。
- 不要分发修改后的可执行文件，不要绕过登录、授权、许可证、加密或付费校验。
- 如果目标是替代采购，应该基于功能需求重新设计和实现，并继续为实际使用的商业工具付费。
- 涉及客户、店铺、账号、订单和 cookie 的数据，必须最小化读取并做脱敏处理。

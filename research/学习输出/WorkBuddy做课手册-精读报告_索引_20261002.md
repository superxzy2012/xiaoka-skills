## 核心结论（10 条）

1. **做课死在哪：不是内容，是顺序。** 必须倒过来：定位 → 标题 → 详情页 → 大纲逐字稿 → 发售。原顺序（先写大纲再想怎么卖）必然失败。
2. **9 环流水线**：定位 → 标题 → 详情页 → 大纲逐字稿 → 发售 → 活动 → 内容 → 上星球 → 复盘。前一环输出是后一环输入。
3. **定位不问你擅长什么，问谁会在什么场景下付钱。** 写窄不是缩小市场，是把「可能买的人」变成「确定要买的人」。
4. **标题不是创作是批量+打分。** 一次出 20 个（作者出了 26 个），6 维度打分，主标题 ≥85 分，红线安全度 = 0 直接淘汰。真能用的那个常在第 12 个之后。
5. **详情页 = 质疑消除单**，不是说明书。作者抄了 20 多条真实「我没买」理由逐条堵掉。七段式顺序不许换。
6. **大纲必须是依赖关系图**，不是并列目录。每讲开头写「上一讲你交出了什么」，结尾写「下一讲要用你哪个文件」。5–11 讲。
7. **先收一笔钱，再把课做完整。** 发售 7+4+4+3 天（预热/开售/追单/收尾），追单期 ≥2 次中途催场。
8. **三条涨价纪律**：一个周期只用一个涨价变量、只涨不返、不做假打折。
9. **知识星球三个实体别搞混**：文章（`articles.zsxq.com/id_xxx.html`）≠ 卡片帖（信息流入口）≠ 专栏（目录集合）。文章不会自动进信息流，必须另发卡片帖挂载。专栏归属是**全量替换**，传空数组会移出全部。
10. **数据纪律**：价格分层（教程正文可写真实数字带来源；对外一律占位）；活动是拉人工具不是收割工具；学员标注「示意」的案例不算真实学员业绩。

## 知识星球写入技术要点（第 10 章）

- 文章 API 核心字段：`group_id` / `title` / `content` / `original_content`（**不用 `topic_id`**）
- 卡片帖正文必须按特定 `req_data` 结构包装并携带 `article_id`，直接传简单结构会返回 `code 1004`
- 修改文章用 **PUT**，不用 PATCH
- 专栏归属：读现有 → 合并去重 → 整表回设
- 频率限制：发文章间隔 ≥25–30 秒，PUT ≥28 秒，专栏归属 ~2 秒；每星球最多约 10 个定时任务，须落在未来 14 天内
- CDN 图片签名会过期，建议首章发出约两周后回读
- 未验证：专栏内主题排序规则

## 数据限制（作者明说）

平台 API 不暴露成员级互动明细。活跃率、互动转化率、新人 7 日留存**拿不到**，需后台导出。做自动化看板前必须先确认数据源，**不能伪造这些指标**。
